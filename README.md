# CLAUDE.md — інструкції для перевірки дипломних робіт

Цей файл — для Claude. Тут описано, як орієнтуватися в репозиторії та як перевіряти роботи студентів.

---

## Контекст репозиторію

Це репозиторій для подання дипломних робіт. Студенти створюють власні папки у `students/<прізвище-і-і>/` та надсилають свої роботи через Pull Request. Науковий керівник (користувач) переглядає роботи разом із тобою.

**Усі відповіді — українською мовою.**

---

## Структура репозиторію

```
diploma-project-2026/

│   ├── Методичні_вказівки_до_виконання_ДП.pdf  # офіційна методичка (першоджерело)
│   ├── methodology.md                          # огляд методички, індекс файлів
│   ├── structure-requirements.md               # структура роботи
│   ├── dstu-requirements.md                    # оформлення за ДСТУ 3008–2015
│   ├── evaluation-criteria.md                  # критерії оцінювання
│   └── review-checklist.md                     # чек-лист перевірки
└── students/
    └── <прізвище-і-і>/
        ├── diploma.pdf                         # сама дипломна

```

## Workflow перевірки

Коли користувач каже «перевір роботу студента ХХХ», «перевір PR #N» або щось подібне:

### Крок 1. Знайди роботу студента

- Якщо вказано прізвище — знайди папку `students/<прізвище-і-і>/`
- Якщо вказано номер PR — переключися на гілку цього PR (через `gh pr checkout <N>`) і визнач, у якій папці зміни
- Якщо нічого не вказано — спитай користувача, яку роботу перевіряти

### Крок 2. Прочитай контекст

**Обов'язково перш ніж перевіряти:**

1. Прочитай `docs/review-checklist.md` — основний чек-лист рев'ю
2. Прочитай `docs/structure-requirements.md` — вимоги до структури
3. Прочитай `docs/dstu-requirements.md` — вимоги ДСТУ 3008–2015
4. Прочитай `docs/evaluation-criteria.md` — критерії оцінювання
5. Прочитай файл дипломної студента (`students/<...>/diploma.pdf` через інструмент Read; для DOCX — спитай, як його обробити; для великих PDF використовуй параметр `pages` обмеженими діапазонами)
6. Прочитай `README.md` студента у його папці (якщо є)

При суперечностях між скіл-файлами у `docs/*.md` та офіційною методичкою `docs/Методичні_вказівки_до_виконання_ДП.pdf` — пріоритет завжди у PDF (першоджерело).

### Крок 3. Перевір за чотирма аспектами

Перевіряй у такому порядку:

1. **Структура** — за `docs/structure-requirements.md`
2. **Оформлення ДСТУ** — за `docs/dstu-requirements.md`
   - **Обов'язково запусти автоматичну перевірку:** `tools/check-formatting <шлях-до-файлу>` (працює з DOCX і PDF). Скрипт перевіряє шрифт, кегль, інтервал, поля, абзацний відступ, формат сторінки, кількість сторінок. Вивід — markdown-таблиця, включай її у свій відгук розділом «Автоматична перевірка форматування». Деталі — у `tools/README.md`.
   - Параметри, які скрипт не покриває (розташування підписів, нумерація сторінок, перенесення слів у заголовках) — перевіряй вручну за `docs/dstu-requirements.md`.
3. **Зміст** — логіка викладу, відповідність темі, обґрунтованість висновків
4. **Граматика та стиль** — науковий стиль, помилки, термінологія

Деталі — у `docs/review-checklist.md`.

### Крок 4. Сформуй відгук

Структура відгуку:

```markdown
## Перевірка дипломної: <ПІБ>

**Версія:** <номер з PR або з README студента>
**Дата перевірки:** <YYYY-MM-DD>

### 1. Структура
- ✅ <що відповідає>
- ⚠️ <зауваження>
- ❌ <критичне порушення>

### 2. Оформлення (ДСТУ)
...

### 3. Зміст
...

### 4. Граматика та стиль
...

### Загальний висновок
<2–4 речення: чи готова робота, які блокери, що першочергово виправити>

### Першочергові правки
1. <конкретна правка з посиланням на сторінку/розділ>
2. ...
```

### Крок 5. Запропонуй опублікувати відгук

Запропонуй користувачу опублікувати відгук як коментар до PR через `gh pr comment <N> --body-file <тимчасовий-файл>`. **Не публікуй автоматично** — спочатку покажи відгук користувачу, дочекайся підтвердження.

## Принципи перевірки

**Будь конкретним.** Замість «потрібно покращити вступ» — «у вступі (с. 4) відсутнє формулювання об’єкта дослідження; за методичкою це обов’язковий пункт».

**Посилайся на джерело вимоги.** Кожне зауваження має посилатися на `docs/methodology.md`, `docs/dstu-requirements.md` або `docs/structure-requirements.md`. Якщо вимога не задокументована — позначай зауваження як рекомендацію, а не як порушення.

**Розділяй критичне та косметичне.**
- `❌` — критичні порушення, без виправлення яких робота не може бути захищена
- `⚠️` — суттєві зауваження, які треба виправити
- 💡 — рекомендації для покращення
- ✅ — те, що зроблено добре

**Не вигадуй вимог.** Якщо у `docs/` немає інформації про якийсь аспект — або спитай користувача, або зазнач, що ти оцінюєш це за загальною академічною практикою, а не за конкретною методичкою.

**Не переписуй роботу за студента.** Твоя задача — вказати на проблему і дати напрям виправлення, а не написати правильний варіант. Виняток — короткі граматичні правки (одне слово / одна фраза), які можна показати як «було → стало».

## Якщо в скіл-файлах чогось не вистачає

Скіли у `docs/*.md` — це витяги з PDF, не повна копія. Якщо тобі треба перевірити аспект, якого немає у скілах (наприклад, специфічна вимога Розділу 4 «Економічна частина» чи Розділу 5 «Охорона праці»):

1. Звернися напряму до `docs/Методичні_вказівки_до_виконання_ДП.pdf` через Read (з параметром `pages` для потрібного діапазону).
2. Не вигадуй вимог з нічого. Якщо в методичці немає чітких правил — позначай зауваження як 💡 (рекомендація), а не як ❌/⚠️.

## Технічні нюанси

- **DOCX-файли:** інструмент Read їх не читає напряму. Конвертуй у markdown через `pandoc <файл.docx> -o /tmp/out.md` і читай результат. Для перевірки форматування — `tools/check-formatting <файл.docx>` (детальніше у `tools/README.md`).
- **PDF-файли:** Read працює з PDF; для великих PDF (>10 сторінок) обов'язково використовуй параметр `pages`.
- **Кирилиця в шляхах:** уникай. Папки студентів — латиницею (це задокументовано у README.md для студентів).

---

## Чого не робити

- Не публікуй коментарі у PR без явного підтвердження користувача
- Не редагуй файли у `students/<інший-студент>/` під час перевірки одного студента
- Не міняй файли у `docs/` під час перевірки — це робота керівника
- Не виставляй балів за 100-бальною шкалою (`docs/evaluation-criteria.md`), якщо користувач про це не просив — за методичкою це робить керівник разом зі студентом
