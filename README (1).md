## Як подати роботу: покрокова інструкція

### 1. Склонуйте репозиторій

```bash
git clone <URL-репозиторію>
cd diploma-project-2026
```

### 2. Створіть власну гілку

Назва гілки: `student/<ваше-прізвище-ім’я-побатькові>` латиницею.

```bash
git checkout -b student/ivanenko-i-i
```

### 3. Створіть папку у `students/`

Назва папки: `<прізвище>-<перша-літера-імені>-<перша-літера-по-батькові>` латиницею, малими літерами, з дефісами.

Приклад: `students/ivanenko-i-i/`

```bash
mkdir students/ivanenko-i-i
```

### 4. Покладіть файл дипломної у вашу папку

Файл називайте `diploma.pdf` або `diploma.docx`. Деталі — в розділі [Формат та іменування файлу](#формат-та-іменування-файлу).

### 5. Закомітьте та запуште зміни

```bash
git add students/ivanenko-i-i/
git commit -m "Iвaненко І.І.: версія 1 дипломної"
git push -u origin student/ivanenko-i-i
```

### 6. Відкрийте Pull Request

- **Base:** `main`
- **Compare:** ваша гілка `student/ivanenko-i-i`
- **Заголовок PR:** `Iвaненко І.І. — версія N`
- **Опис PR:** коротко зазначте, що змінилося порівняно з минулою версією (для першої версії — просто «перша подача»).

Після відкриття PR науковий керівник побачить роботу та запустить перевірку.

## Структура папки студента

Усередині `students/<ваше-прізвище-і-і>/` має бути:

```
students/ivanenko-i-i/
├── diploma.pdf          # сам файл дипломної (обов’язково)
└── README.md            # короткі дані про роботу (опціонально, але бажано)
```

`README.md` у вашій папці може містити:

- ПІБ повністю
- Тема дипломної
- Науковий керівник
- Спеціальність та група
- Поточну версію та коротку історію змін

Приклад:

```markdown
# Іваненко Іван Іванович

- **Тема:** Розробка системи автоматизованої перевірки текстових документів
- **Керівник:** Петренко П.П.
- **Спеціальність / група:** 121 КН-41
- **Поточна версія:** 2
- **Зміни у v2:** додано розділ 3, виправлено зауваження до вступу
```

## Формат та іменування файлу

- **Прийнятні формати:** `PDF` (рекомендовано) або `DOCX`.
- **Назва файлу:** `diploma.pdf` (одна назва, версії — через історію Git).
- **Без пробілів та кирилиці у назві файлу.**
- **Розмір:** до 100 МБ. Якщо більше — стисніть PDF.

> Не створюйте `diploma-v1.pdf`, `diploma-final.pdf`, `diploma-final-final.pdf`. Версії автоматично зберігає Git. Один файл — `diploma.pdf` — який ви оновлюєте.

### Самоперевірка перед подачею

У репо є утиліта `tools/check-formatting`, яка автоматично перевіряє ваш файл за ключовими вимогами ДСТУ (шрифт, кегль, інтервали, поля, абзацний відступ, формат сторінки, кількість сторінок):

```bash
tools/check-formatting students/<ваша-папка>/diploma.docx
```

Запустіть її **перед** відкриттям PR — це врятує одну ітерацію зауважень. Деталі — у [`tools/README.md`](tools/README.md).

## Версіонування

Кожна нова версія дипломної — це **новий PR** (або новий commit у вже відкритому PR, якщо попередню версію ще не змерджено).

**Як подати нову версію:**

1. Переключіться на свою гілку: `git checkout student/ivanenko-i-i`
2. Якщо попередня версія вже змерджена в `main`, спочатку синхронізуйтеся: `git pull origin main`
3. Замініть файл `diploma.pdf` новим
4. Закомітьте з осмисленим повідомленням: `git commit -am "Іваненко І.І.: версія 3 — додано розділ 4"`
5. Запуште та відкрийте новий PR (або оновіть існуючий)

## Як відбувається перевірка

Науковий керівник переглядає вашу роботу за допомогою Claude. Claude перевіряє чотири аспекти:

1. **Відповідність структурі методички** — наявність та порядок розділів, обсяги.
2. **Оформлення за ДСТУ** — шрифти, інтервали, поля, підписи рисунків і таблиць, оформлення списку літератури.
3. **Якість змісту** — логіка викладу, обґрунтованість висновків, відповідність темі.
4. **Граматика та стиль** — науковий стиль, граматичні помилки, термінологія.

Детальний чек-лист — у [`docs/review-checklist.md`](docs/review-checklist.md).

Результат перевірки публікується як коментар до вашого PR.

---

## Робота з коментарями

1. Уважно прочитайте коментар від рецензента.
2. Виправте зауваження у своєму файлі.
3. Закомітьте зміни у ту саму гілку — PR оновиться автоматично.
4. У коментарі до PR коротко напишіть, які саме зауваження ви виправили.

> Якщо щось у коментарі неясно — задайте уточнювальне питання прямо в PR, а не починайте виправляти наосліп.

## Часті питання

**Чи можна редагувати чужі папки?**
Ні. Працюйте тільки у власній папці `students/<ваше-прізвище-і-і>/`.

**Що, якщо я помилився у назві гілки чи папки?**
Перейменуйте локально, запуште заново. Стару гілку видаліть.

**Що, якщо я не знаю Git?**
Подивіться короткий курс — https://git-scm.com/book/uk/v2. Достатньо знати: `clone`, `checkout -b`, `add`, `commit`, `push`. Для PR — інтерфейс GitHub.

**Чи можу я закомітити вихідний код програмної частини?**
Ні. Цей репозиторій — лише для тексту дипломної. Якщо потрібно подати код — узгодьте окремо з керівником.

**Хто бачить мою роботу?**
Усі, хто має доступ до цього репозиторію (інші студенти та керівник). Не комітьте сюди нічого, що не має бути публічним у межах групи.

---

Питання, які не вирішуються через PR — звертайтесь до наукового керівника напряму.
